# KoeLoop

**声で話す、声が返る。そのまま会話が続く。**

KoeLoop（こえループ）は、ローカルの音声認識、OpenAI互換LLM、VOICEVOXを組み合わせた、日本語向けの音声会話Webアプリです。LLMのストリーミング出力を文・節へ再分割し、返答が完成する前から読み上げます。

```text
マイク → Silero VAD → Parakeet → OpenAI互換LLM
                                  ↓
ブラウザで再生 ← VOICEVOX ← 文・節への再分割
```

> **ローカル／信頼できるLAN内で使う実験的なアプリです。認証はありません。**
> このソースコードのPublic公開は、アプリをインターネットへ公開してよいことを意味しません。
> 公開トンネルやポート転送で公開せず、bind先とファイアウォールでアクセスを制限してください。

## 主な機能

- 会話履歴つきのチャット画面 `/` と、分割・音声合成の比較ラボ `/lab`。
- マイク入力 → 発話終了の検出 → ローカル認識 → LLM → 音声返答。
- 1回ごとの音声会話と、返答後に聞き取りへ自動で戻るハンズフリー連続会話。
- **実験的な音声割り込み**：返答中に話し始めると返答を止め、次の発話を取り込む。
- 自動送信せず、文字起こしを入力欄へ追加する通常の「マイク」モード。
- OpenAI互換のChat CompletionsストリーミングAPIに対応。接続先・モデル・話者・速度を画面で変更可能。
- 文末、文・節のバランス、構文解析、受信チャンクそのまま、の読み上げ方式を比較。
- 句点後の追加無音、読点ポーズ倍率、再生待ち上限、生成・再生の停止。

音声は**発話単位で完成したWAV**を順次配信します。VOICEVOX内部の生成途中の音声をストリーミングする実装ではありません。

## クイックスタート（推奨：Nix / Linux）

### 1. ソースを取得

```sh
git clone https://github.com/upiscium/koeloop.git
cd koeloop
```

Nixのflakesを利用できる環境が必要です。検証済みホストは **x86_64-linux** です。aarch64-linuxの定義もありますが、実行確認はしていません。

### 2. VOICEVOX EngineとLLMを用意

- **VOICEVOX Engine**：例 `http://127.0.0.1:50021`。Engine・話者は各利用規約に従って利用してください。
- **LLM**：OllamaなどのOpenAI互換API。例 `http://127.0.0.1:11434/v1`。使用するモデルを事前に導入してください。

既存のVOICEVOX Engineがなければ、Dockerで公式CPUイメージを起動できます。Dockerは別途必要です。このコマンドはEngineを**ループバックにだけ**公開します。

```sh
docker run --rm --name koeloop-voicevox \
  -p 127.0.0.1:50021:50021 \
  voicevox/voicevox_engine@sha256:eb8c7f46a7d01217d1ff2b6f018261faedeceded3cc756b4fbbf371791ad6c90
```

### 3. 音声会話用の環境で起動

```sh
nix develop .#voice -c uvicorn restream.app:app \
  --host 127.0.0.1 --port 8000 --ws-max-size 65536
```

初回は依存パッケージと固定リビジョンのモデルをダウンロードします。音声会話用の `.#voice` は **Silero VAD + Parakeet / CPU** を利用し、Vosk・PyTorchは含めません。モデル取得量とディスク容量に注意してください。

### 4. ブラウザで設定

`http://127.0.0.1:8000` を開き、接続設定を確認します。

| 項目 | 例 |
|---|---|
| LLMのURL | `http://127.0.0.1:11434/v1` |
| モデル名 | 導入済みのモデル名（例：`qwen3.5:4b`） |
| VOICEVOXのURL | `http://127.0.0.1:50021` |
| 話者 | 「話者を取得」から選択 |
| 推論モード | 接続先の既定値。対応するモデルのみ `none` などを指定 |

URLは**APIサーバーから見た接続先**です。ブラウザを別端末で開く場合も同じです。LLMのネイティブAPIではなく、OpenAI互換APIを使ってください。

## 音声で会話する

### 連続会話

1. 下書きを空にして **「連続会話を開始」** を押す。
2. マイクを許可し、**「聞いています」** と表示されてから話す。
3. 無音が設定時間続くと発話を確定し、Parakeetで認識する。
4. 最終認識文だけをLLMへ送り、ユーザー発話として会話履歴に表示する。
5. 返答の再生が完了すると、500ms待って次の発話待ちへ戻る。
6. **「会話を終了」** でマイクを解放し、進行中の返答も止める。

録音中は途中テキストを表示しません。1回の明示操作で連続会話を開始しますが、再読み込みやタブ復帰で自動開始はしません。

割り込みオフでは、認識・LLM応答・再生・再開前の待機中はマイクの音声トラックを無効化し、取り込みグラフを切断します。その間の音声は処理・送信・後送りしません。マイク接続自体は同じものを保持するため、ブラウザやOSのマイク使用表示は続く場合があります。

### 返答への割り込み（実験）

開始前に **「連続会話で返答中の割り込みを有効にする（実験）」** をオンにします。既定はオフです。設定は保存されますが、会話セッション自体は保存しません。

- LLMの生成・読み上げ中にも、マイクのPCM音声をAPIサーバーのVADへ送信します。
- 発話を確認すると、現在の返答の生成・再生を中断します。
- その瞬間に録音やVADを作り直さず、すでに取り込んだ冒頭も含めて発話終了まで保持します。
- 認識できた最終文を次の質問として1回送ります。
- 中断した往復（質問と返答）は画面に残りますが、次のLLM履歴からは除外します。完了済みの往復は保持します。
- 返答が自然に終わった場合、すでに動いている監視をそのまま次の聞き取りへ引き継ぎます。監視の準備前に返答が完了した場合は準備を閉じ、500ms待って通常の設定で聞き取りを再開します。

**まずはヘッドホンでの利用を推奨します。** ブラウザのエコーキャンセル・ノイズ抑制は要求していますが、スピーカー音を人の発話と区別できる保証はありません。反響や雑音で誤割り込みする場合があります。Parakeet認識中は割り込めません。監視準備前や待受け窓の更新中に始まった音声は回復できません。

### その他の入力モード

- **「音声で会話」**：1発話だけ認識・送信し、次はボタンを押し直す方式。
- **「マイク」**：停止後に文字起こしを入力欄へ追加するだけ。内容を確認・修正してから手動送信する方式。**LLMへ自動送信しません。**
- テキスト：Enterで送信、Shift+Enterで改行。日本語IMEの変換確定では送信しません。

### 発話終了の調整

「音声会話の発話検出」で調整できます。

| 設定 | 初期値 | 範囲 |
|---|---:|---|
| 発話終了の無音待ち | 1000ms | 500〜3000ms |
| 発話前の余白 | 200ms | 0〜500ms |
| 発話後の余白 | 200ms | 0〜500ms |
| VADしきい値 | 0.5 | 0.1〜0.9 |

言いよどみで切れる場合は無音待ちを1500〜2000msなどへ延ばしてください。応答開始もその分遅くなります。VADは発話の意味を判断しません。短いノイズを抑えるため250ms以上の肯定フレームを確認しますが、短い返事を拾わない場合があります。

割り込み監視では `max(設定したしきい値, 0.65)` を使います。監視を次の聞き取りに引き継いだ区間もその値を維持します。

## 安全性と制約

- **認証なし・ローカル／信頼できるLAN向け**です。APIサーバー自身による接続元のLAN限定はありません。
- 利用者は任意のHTTP(S)バックエンドを選べます。サーバーから到達可能なサービスへのリクエストを発生させられるため、不特定の利用者へ公開しないでください。URL検証は完全なSSRF対策ではありません。
- クラウドLLMを選ぶと認識テキストと会話履歴が接続先へ送信され、費用が生じる場合があります。LLM接続先を変えると次回は履歴も新しい接続先へ送られます。
- ローカルSTT経路はブラウザのWeb Speech APIや外部STTサービスを使いません。モデルは環境構築時に取得します。
- 設定はlocalStorageに保存しますが、APIキー・会話本文・録音を永続保存しません。キーはこのタブだけで保持し、通常運用では認識本文をサーバーログへ出しません。
- サーバー設定のAPIキーは、同じ正規化済みLLM接続先にだけ利用します。別のURLへ転送しません。
- 音声会話開始時は空の下書きが必要です。連続会話中は通常の送信・マイク・接続設定の変更を無効化します。
- 「会話を終了」「停止」「新しい会話」、タブ非表示・ページ離脱、マイク切断、エラーで会話を止めます。遅れて返った結果で再開・送信しません。
- 1つの録音／待受け窓は最大30秒です。無音窓は送信せず更新します。発話を含む窓が上限に達した場合は、途中の可能性があるため認識・送信せず終了します。
- 音声認識・空結果・通信・再生などの失敗時は連続会話を終了します。明示的な未受付429だけは上限付きの待機後に再試行します。
- VADと一括STTは1つの実行枠を共有します。入力キュー、チャンクサイズ、録音時間、認識時間に上限があります。
- 誤認識はあり得ます。送信前の確認が必要なら、通常の「マイク」を使ってください。

### 別端末のマイクにはHTTPSが必要

ブラウザのマイクは **localhostまたは信頼済みHTTPS** でのみ使えます。通常の `http://192.168.x.x:8000` では利用できません。

信頼済みHTTPSを用意するか、例えば利用端末でSSHトンネルを張ってlocalhostから利用してください。

```sh
ssh -N -L 127.0.0.1:8000:127.0.0.1:8000 USER@SERVER
```

サーバー側はループバックにbindし、利用端末では `http://127.0.0.1:8000` を開きます。ブラウザのセキュリティ制限を無効化する必要はありません。

## 読み上げの比較

チャットの「詳細設定」または `/lab` で選べます。

| 方式 | 挙動 |
|---|---|
| バランス | 文末を優先し、長い文は節や読点で分割 |
| 文末 | 原則として文末まで待つ比較基準 |
| 構文解析 | 日本語の品詞・係り受けと先読みの安定性から慎重に分割（実験） |
| そのまま | LLMのcontent差分ごとに合成。細切れで不自然になりやすい比較用 |

句点後の追加無音は初期値200ms、読点ポーズ倍率は0.8です。個別調整・無効化できます。構文解析はspaCyと日本語モデルを利用し、速さや自然さの向上を保証しません。

## 開発環境

### Nix環境の選択

| 環境 | 用途 |
|---|---|
| `nix develop` | テキスト会話、構文解析、Whisper baseの通常マイク |
| `nix develop .#voice` | 推奨の音声会話：Silero VAD + Parakeet / CPU |
| `nix develop .#voice-browser` | 上記とブラウザ検証用のChromium / Playwright |
| `nix develop .#browser` | モデルを模擬するブラウザ検証 |
| `nix develop .#parakeet` | Parakeet用（VADも含む） |
| `nix develop .#vosk` | Voskによる通常の一括マイク入力 |
| `nix develop .#whisper-ja` / `.#wav2vec-ja` | 任意の日本語微調整モデルの比較 |
| `nix develop .#stt-eval` | 全候補モデルの比較。取得量が大きいので注意 |

Voskの逐次入力は過去の比較実験用です。現在の音声会話経路はVoskを使いません。

### 通常のPython環境

Python 3.11以上で、テキスト会話・ラボを起動できます。

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[test]'
uvicorn restream.app:app --host 127.0.0.1 --port 8000 --ws-max-size 65536
```

音声会話・構文解析を利用する場合は追加依存とモデルが必要です。再現しやすいNix環境を推奨します。Pythonでは `.[parakeet,syntax]` を導入し、`STT_PARAKEET_MODEL_DIR` と `STT_VAD_MODEL_PATH` にモデルのローカル配置先を指定してください。固定モデルの出典は [THIRD_PARTY.md](THIRD_PARTY.md) とNix定義を参照してください。

| 環境変数 | 用途 |
|---|---|
| `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY` | サーバー側のLLM設定（キーは任意） |
| `VOICEVOX_URL` | サーバーから見たEngineのURL |
| `STT_BACKEND` | 通常マイクの初期モデル。`whisper` / `parakeet` 等 |
| `STT_MODEL_PATH`, `STT_COMMAND` | whisper.cppモデルとCLI |
| `STT_PARAKEET_MODEL_DIR` | Parakeet ONNXモデルのローカル配置先 |
| `STT_VAD_MODEL_PATH` | Silero VAD ONNXファイル |
| `STT_THREADS` | STT用CPUスレッド数。既定4、1〜8に制限 |

音声モデルはブラウザから任意パスを指定できません。Parakeetは発話ごとに子プロセスで実行するCPU方式です。サーバーの遠隔GPUへ自動転送する機能はありません。

## テスト

### 外部サービス不要

```sh
nix flake check -L
nix develop -c ruff check restream tests examples
nix develop .#browser -c python -m examples.browser_smoke
nix develop .#browser -c python -m examples.browser_stt_smoke
nix develop .#browser -c python -m examples.browser_voice_smoke
nix develop .#browser -c python -m examples.browser_voice_refine
nix develop .#browser -c python -m examples.browser_voice_continuous
nix develop .#browser -c python -m examples.browser_voice_barge
```

flakeチェックはPython単体・模擬結合テスト、JavaScript構文、PCM・リサンプル・録音上限のNodeテストを実行します。ブラウザ試験は偽マイクと模擬VAD/STT/LLM/VOICEVOXを使い、実際のAudioWorklet、WebSocket、WAV、Web Audio再生を検証します。

連続会話・割り込み試験には、複数ターン、履歴、再生完了、割り込み後の録音範囲、遅いモデル準備、停止・画面非表示・エラー時の後始末を含みます。**実マイク、スピーカー反響の除去、人が聴いた自然さを保証するテストではありません。**

### 実モデル・実サービスを使う任意の試験

音声ファイルはリポジトリに含めません。VOICEVOX Engineが起動している場合、公開用の固定文を合成して準備できます。

```sh
nix develop -c python -m examples.stt_number_fixtures \
  --output artifacts/stt-number-fixtures
nix develop .#voice -c python -m examples.vad_probe \
  --output artifacts/my-vad-probe.json
nix develop .#voice-browser -c python -m examples.browser_voice_smoke \
  --real-stt --output artifacts/my-real-stt-check
```

全段を実サービスで試す `examples.browser_voice_live` は、実LLMへ認識文を送信してVOICEVOXを呼びます。接続先・モデルを確認して明示的に実行してください。

診断コマンドは `artifacts/` 以下など、指定した場所に音声・認識文・接続情報を保存する場合があります。通常のWebUIは保存しません。私的な音声・キー・検証記録をコミットしないでください。初期公開には音声ファイル・個人環境の運用メモ・モデル本体を含めていません。
